===============
Решение проблем
===============

Восстановление после жёсткого выключения
----------------------------------------

::

	[2020-11-27 10:40:01.764013860][th:1][warning] Irohad/Storage/FlatFileBlockStorage Error while block deserialization: Unexpected end of string. Expected a value.

	^

::

	[2020-11-25 10:36:19.993552669][C][Init]: Irohad startup failed: WSV state (height 4576773) is more recent than block storage (height 4576772).

Такие сообщения могут появиться, если узел упал при использовании
файлового хранилища блоков. Скопируйте недостающие блоки с
другого узла — в этом случае можно использовать флаг
``--reuse_state`` для быстрого запуска — или удалите блоки,
начиная с пустого файла, и пересоздайте WSV из существующих
блоков.

Отключение клиентов или ошибки "Rendezvous" после долгих периодов
простоя
-------------------------------------------------------------------

Если клиенты (особенно долгоживущие потоки статусов) периодически
теряют соединение с Torii после многих часов бездействия,
причиной обычно является таймаут простоя на промежуточном хопе
(NAT, балансировщик, прокси), который молча разрывает соединение
HTTP/2.

Этот форк ``irohad`` включает **gRPC keepalive ping** на всех
своих серверах (Torii, internal ordering, utility): сервер
пингует простаивающие соединения каждые 60 секунд и закрывает
мёртвые через 20-секундный таймаут, поэтому клиенты
переподключаются чисто вместо зависания на полузакрытом канале.

Если вы всё ещё видите обрывы:

- убедитесь, что используете сборку с фиксом keepalive (этот форк,
  ветка ``iroha1-main``);
- проверьте, есть ли у прокси/LB между клиентом и узлом
  собственный таймаут простоя короче интервала keepalive, и
  увеличьте его;
- для потоков статусов предпочитайте переподключение с backoff —
  см. ``stale_stream_max_rounds`` в :ref:`configuration`.
