Советы по безопасности установки Iroha
======================================

Это руководство предназначено для защиты установки Iroha.
Большинство шагов из этого руководства могут показаться
очевидными, но они помогают избежать возможных проблем
безопасности в будущем.

Физическая безопасность
^^^^^^^^^^^^^^^^^^^^^^^

Если серверы расположены локально (физически доступны), нужно
применить ряд мер безопасности. Пропустите эти шаги, если
используется облачный хостинг.

Установите организационную политику и/или систему контроля
доступа так, чтобы только уполномоченный персонал имел доступ к
серверной.
Затем установите пароль BIOS/firmware и настройте порядок
загрузки, чтобы предотвратить несанкционированную загрузку с
других носителей.
Убедитесь, что загрузчик защищён паролем, если такая
функциональность есть. Также хорошо иметь видеонаблюдение CCTV.

Развёртывание
^^^^^^^^^^^^^

Во-первых, проверьте, что для загрузки `исходного кода
<https://github.com/baziorek/iroha1-cpp>`__ (форк сообщества
`hyperledger-iroha/iroha
<https://github.com/hyperledger-iroha/iroha/tree/iroha1-main>`__)
и `docker-образов
<https://hub.docker.com/r/hyperledger/iroha>`__ используется
официальный репозиторий.
Измените любые пароли по умолчанию, используемые при установке,
например пароль для подключения к postgres.
Репозиторий Iroha содержит примеры приватных и публичных ключей —
никогда не используйте их в продакшене.
Кроме того, проверьте, что новые пары ключей генерируются в
безопасной среде и только администратор имеет доступ к этим
парам ключей (или хотя бы минимизируйте количество людей).
После развёртывания ключей на пирах Iroha удалите приватные
ключи с хоста, использованного для развёртывания, т.е. приватные
ключи должны находиться только внутри пиров Iroha.
Создайте зашифрованную резервную копию приватных ключей перед их
удалением и ограничьте к ней доступ.

Настройка сети
^^^^^^^^^^^^^^

Iroha прослушивает порты 50051 и 10001, и опционально 55552, если
включён TLS.
Настройки файрвола должны разрешать входящие/исходящие
соединения к/от этих портов.
По возможности отключите или удалите любые другие сетевые
службы с прослушиваемыми портами (FTP, DNS, LDAP, SMB, DHCP,
NFS, SNMP и т.д.).
В идеале Iroha должна быть максимально изолирована с точки зрения
сети.

Вы можете включить TLS на портах torii, если хотите шифровать
связь клиент-пир.

Если вы не используете шифрование трафика, настоятельно
рекомендуем использовать VPN или Calico для настройки
overlay-сети Docker, т.е. любого механизма, позволяющего
шифровать связь между пирами.
Docker swarm шифрует коммуникации по умолчанию, но не забудьте
открыть необходимые порты в конфигурации файрвола.
Если используется VPN, проверьте, что VPN-ключ недоступен
другим пользователям.

Если используется SSH, отключите вход root.
Кроме того, отключите аутентификацию по паролю и используйте
только ключи.
Также может помочь установка уровня логирования SSH на INFO.

Если IPv6 не используется, отключение может быть хорошей идеей.

Обновления
^^^^^^^^^^

Установите последние патчи безопасности операционной системы и
регулярно её обновляйте.
Если Iroha работает в docker-контейнерах, регулярно
обновляйте Docker.
Хотя это опционально, хорошей практикой считается тестировать
обновления на отдельном сервере перед установкой в продакшен.

Логирование и мониторинг
^^^^^^^^^^^^^^^^^^^^^^^^

- Собирайте и отправляйте логи на выделенную машину с помощью
  агента (например, Filebeat).
- Собирайте логи со всех пиров Iroha в центральной точке
  (например, Logstash).
- Передавайте информацию логирования и мониторинга по
  зашифрованному каналу (например, https).
- Настройте механизм аутентификации, чтобы предотвратить доступ
  третьих лиц к логам.
- Настройте механизм аутентификации, чтобы предотвратить
  отправку логов третьими лицами.
- Логируйте весь доступ администратора.

Усиление ОС
^^^^^^^^^^^

Следующие шаги предполагают, что Docker используется для
запуска Iroha.

- Включите и настройте Docker Content Trust.
- Разрешите управлять docker-демоном только доверенным
  пользователям.
- Установите лимит для ресурсов docker-контейнера.
