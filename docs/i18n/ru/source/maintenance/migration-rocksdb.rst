====================
Миграция на RocksDB
====================

Iroha позволяет использовать Postgres или Rocks Database.
Вы можете использовать предпочитаемый вариант, а если хотите
переключиться — есть вариант и для вас.
**Просто мигрируйте вашу базу данных!**
Вот как

.. hint:: И инструмент миграции, и WSV checker имеют ``-help``,
   который можно вызвать, чтобы в любое время проверить доступные
   флаги.

Как мигрировать
===============

После сборки Iroha (или просто pull docker-образа
<https://hub.docker.com/r/hyperledger/iroha>`_) версии 1.3 (или
новее) у вас уже есть инструменты миграции как отдельный
исполняемый файл! По умолчанию после сборки Iroha хранит
бинарники в ``BUILD_DIR/bin/``.

Просто запустите ``iroha_migrate`` со следующими флагами:

- ``-help`` - помощь
- ``-block_store_path`` - указывает путь к block store. По
  умолчанию: "/tmp/block_store"
- ``-export`` - экспортирует block store в указанную директорию,
  по умолчанию — текущая рабочая директория (CWD). Используйте
  для *обратной* миграции на RocksDB (экспортируя файлы из неё).
- ``-drop_state`` - используйте для перезаписи блоков в blockstore
  RocksDB, если он уже существует. Может быть очень полезно, если
  следующий шаг — проверка корректности мигрированной базы —
  пройдёт с ошибками и нужно будет повторить процесс миграции.
  По умолчанию: false
- ``-rocksdb_path`` - указывает путь к RocksDB. По умолчанию:
  "rocks.db"

Если миграция не удастся, она завершится с ненулевым кодом. В этом
случае проверьте все флаги и попробуйте снова.


И... ваша база данных мигрирована! Но это ещё не всё.

Чтобы убедиться, что процесс миграции прошёл успешно, затем
используйте проверку WSV.

Как проверить WSV после миграции
================================

Запустите ``iroha_wsv_diff`` со следующими флагами:

- ``-help`` - помощь
- ``-pg_opt`` - указывает строку опций Postgres. Она должна быть
  как в вашей конфигурации. По умолчанию:
  "dbname=iroha_default host=localhost port=5432 user=postgres
  password=postgres"
- ``-rocksdb_path`` - указывает путь к RocksDB. По умолчанию:
  "rocks.db"

Если базы одинаковы, вы увидите мистера Спока. Также (если вы не
большой фанат научной фантастики) код выхода будет нулевым.

Если есть различия, мы рекомендуем снова использовать
инструмент миграции с флагом ``-drop_state``.

В случае расхождений команда завершится с ненулевым кодом.
Различия будут выведены в консоль, а полные WSV обеих баз будут
сохранены в соответствующие файлы (результат в виде
``postgres.wsv`` и ``rocksdb.wsv`` будет в текущей рабочей
директории (CWD)). Для будущих исследований вы можете
использовать любой diff-инструмент, чтобы увидеть точные
различия между WSV.
