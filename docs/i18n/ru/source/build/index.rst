.. _build-guide:

================
Сборка Iroha
================

В этом руководстве мы научимся устанавливать все зависимости, необходимые для сборки
Iroha, и как собственно её собирать.

Всего будет 3 шага:

#. Установка предварительных требований окружения

#. Установка зависимостей Iroha (для Docker выполняется автоматически)

#. Сборка Iroha

.. note:: Для начала работы с Iroha собирать её не обязательно.
  Вместо этого можно скачать готовый образ Docker из Hub —
  этот процесс подробно описан на странице :ref:`getting-started` данной документации.

Предварительные требования
==========================

Чтобы успешно собрать Iroha, нужно подготовить окружение.
Существует несколько способов сделать это, и мы опишем их все.

В настоящее время мы поддерживаем Unix-подобные системы (по сути, мы ориентируемся на популярные
дистрибутивы Linux и MacOS). Если у вас Windows или вы не хотите
тратить время на установку всех зависимостей, возможно, стоит рассмотреть использование окружения
Docker. Также пользователи Windows могут рассмотреть возможность использования
`WSL <https://en.wikipedia.org/wiki/Windows_Subsystem_for_Linux>`_

Технически Iroha может быть собрана под Windows нативно в экспериментальном режиме.
Это руководство также охватывает этот способ.
Все этапы, связанные со сборкой под Windows, отделены от основного потока из-за значительных отличий.

Пожалуйста, выберите вашу платформу ниже для быстрого доступа:

    - :ref:`docker-pre`
    - :ref:`linux-pre`
    - :ref:`MacOS-pre`
    - :ref:`Windows-pre`


.. hint:: Возникли трудности? Проверьте раздел FAQ или свяжитесь с нами напрямую,
  если застряли на чём-то. Мы не ожидаем, что это произойдёт, но некоторые
  проблемы с окружением возможны.

.. _docker-pre:

Docker
^^^^^^

Идея поддержания актуальных образов Docker заключается в возможности запускать Iroha без необходимости её сборки.
Но теперь у вас есть возможность запускать не только готовые к использованию образы, но и специальный **Iroha Builder** внутри Docker, чтобы собрать Iroha так, как вам нужно.

Прежде всего, вам нужно установить ``docker`` и ``docker-compose``. Вы можете
прочитать, как установить их, на
`сайте Docker <https://www.docker.com/community-edition/>`_

.. note:: Пожалуйста, используйте последнюю доступную версию docker-демона и docker-compose.

Образы Iroha
"""""""""""""""

Все образы Iroha для Docker можно найти, `выполнив поиск в Docker Hub <https://hub.docker.com/search?q=hyperledger%2Firoha&type=image>`_ или на `GitHub <https://github.com/orgs/hyperledger/packages?repo_name=iroha>`_.

В настоящее время существуют следующие образы:

- ``iroha`` -- общая сборка Iroha 1.x (артефакт из апстрима на Docker Hub);
- ``iroha-burrow`` -- сборка Iroha 1.x с `интеграцией Burrow <../integrations/index.html#hyperledger-burrow>`_ (устарело: Burrow достиг EOL);
- ``iroha-ursa`` -- сборка Iroha 1.x с `интеграцией Ursa <../integrations/index.html#hyperledger-ursa>`_ (устарело: Ursa достиг EOL);
- ``iroha2`` -- сборка Iroha 2;
- ``iroha-builder`` -- специальный образ, позволяющий запустить конструктор Iroha внутри Docker.

.. hint:: Подробнее о запуске образов можно прочитать в `Руководстве по быстрому старту <../getting_started/index.html>`_.

Каждый образ можно использовать с соответствующим тегом, указывающим ветку, из которой собран образ.
Все доступные теги можно найти на Docker Hub. `Вот все теги <https://hub.docker.com/r/hyperledger/iroha/tags>`_ для образа ``iroha``.

Например, ``iroha:1.6.0`` — это последняя сборка Iroha 1. **Не** используйте теги ``latest``, ``develop`` или ``main`` — они теперь указывают на сборки Iroha 2 (Rust) или устаревшие артефакты 2022 года. 

Образы форка на GHCR
"""""""""""""""""""""

CI форка ``baziorek/iroha1-cpp`` дополнительно публикует образы в
**GitHub Container Registry** под ``ghcr.io/baziorek/iroha1-cpp``.
В настоящее время публикуется только образ **builder** (задачи runtime-
образов ``docker/release`` отключены в workflow) с тегами,
совпадающими с именами веток — например, ``iroha1-main`` — и релизными тегами:

.. code-block:: shell

  docker pull ghcr.io/baziorek/iroha1-cpp:iroha1-main

Используйте его точно так же, как ``hyperledger/iroha-builder`` ниже, но учтите, что он
собран из текущих исходников форка, поэтому его набор инструментов соответствует тому, что нужно
репозиторию сегодня.


Конструктор Iroha
"""""""""""""""""

.. note:: Образ ``hyperledger/iroha-builder`` — это артефакт апстрима,
  который не пересобирался с тех пор, как Iroha 1 была объявлена устаревшей в апстриме; его
  набор инструментов может быть слишком старым для текущих исходников. Предпочтительнее собирать
  нативно или в собственном контейнере — шаги ниже всё равно сработают, если образ
  окажется достаточно новым.

Конструктор Iroha позволяет собирать Iroha с `любыми из параметров, доступных <Параметры CMake_>`_ для любой другой платформы, но делать это удобно и безопасно в Docker. 

Вот шаги: 

1. Прежде всего, запустим конструктор:

.. code-block:: shell

  docker run -it hyperledger/iroha-builder:latest

На этом шаге вы запустите и запустите образ в контейнере в интерактивном режиме. Вы можете использовать любой доступный тег, по умолчанию это ``latest``, а тег для разработки — ``develop``. Обратите внимание, что вам может потребоваться выполнить некоторые действия с правами ``sudo``.

2. Когда вы внутри контейнера, склонируйте репозиторий Iroha: 

.. code-block:: shell

  git clone https://github.com/baziorek/iroha1-cpp.git

3. Когда Iroha склонирована, перейдите в папку Iroha: 

.. code-block:: shell

  cd iroha1-cpp

4. Затем запустите скрипт, который соберёт все необходимые зависимости через vcpkg: 

.. code-block:: shell

  ./vcpkg/build_iroha_deps.sh $PWD/vcpkg-build



.. _linux-pre:

Linux
^^^^^

Чтобы собрать Iroha, вам понадобятся следующие пакеты:

``build-essential`` ``git`` ``ca-certificates`` ``tar`` ``ninja-build`` ``curl`` ``unzip`` ``cmake``

Используйте этот код для установки зависимостей окружения в дистрибутиве Linux на базе Debian.

.. code-block:: shell

  apt-get update; \
  apt-get -y --no-install-recommends install \
  build-essential ninja-build \
  git ca-certificates tar curl unzip cmake \
  pkg-config zip

.. note:: Инструмент тестирования WSV-diff ``test/tool/test_tool_iroha_wsv_diff.sh``
  дополнительно требует ``jq`` и ``postgresql-client`` (для ``psql``)
  на машине, где запускаются тесты.

.. Important:: Если вы планируете использовать `интеграцию Burrow <../integrations/burrow.html>`_, вам также понадобится GO. Установите его, следуя инструкциям на `официальном сайте <https://golang.org/doc/install>`_, а затем выполните следующую команду:

.. code-block:: shell

  go get github.com/golang/protobuf/protoc-gen-go

.. note::  Если вы планируете активно разрабатывать Iroha и собирать общие
  библиотеки, рассмотрите возможность установки
  `последней версии <https://cmake.org/download/>`_ CMake.

RaspberryPi 4
"""""""""""""""""""

Чтобы собрать Iroha на Raspberry Pi 4, следуйте тем же инструкциям, что и для сборки под Linux. 

**ВНИМАНИЕ**: Iroha требует 8 ГиБ оперативной памяти. Если ваша сборка завершается с `SIGKILL`, рассмотрите возможность создания swap-файла или swap-раздела на хост-устройстве либо кросс-компиляцию. 

Теперь вы готовы `установить зависимости Iroha <Установка зависимостей с помощью Vcpkg_>`_.

.. _macos-pre:

MacOS
^^^^^

Если вы хотите собрать Iroha с нуля и активно её разрабатывать, используйте следующий код
для установки всех зависимостей окружения с помощью Homebrew:

.. code-block:: shell

  xcode-select --install
  brew install cmake go pkg-config coreutils ninja git gcc@9

.. hint:: Чтобы установить сам Homebrew, выполните

  ``ruby -e "$(curl -fsSL https://raw.githubusercontent.com/homebrew/install/master/install)"``

.. Important:: Если вы планируете использовать `интеграцию Burrow <../integrations/burrow.html>`_, вам также понадобится GO. Установите его, следуя инструкциям на `официальном сайте <https://golang.org/doc/install>`_, а затем выполните следующую команду:

.. code-block:: shell

  go get github.com/golang/protobuf/protoc-gen-go

Теперь вы готовы `установить зависимости Iroha <Установка зависимостей с помощью Vcpkg_>`_.

.. _windows-pre:

Windows
^^^^^^^

.. note:: Все перечисленные команды предназначены для сборки 64-битной версии Iroha.

Менеджер пакетов Chocolatey
""""""""""""""""""""""""""""""

Прежде всего вам нужно установить менеджер пакетов Chocolatey.
Обратитесь к `руководству <https://chocolatey.org/install>`_ по установке Chocolatey.

Сборка набора инструментов
"""""""""""""""""""""""""""""

Установите CMake, Git и компиляторы Microsoft через Chocolatey в режиме командной строки с правами администратора:

.. code-block:: shell

  choco install cmake git visualstudio2019-workload-vctools ninja


PostgreSQL не является зависимостью сборки, но её рекомендуется установить сейчас для последующего тестирования:

  .. code-block:: shell

    choco install postgresql
    # Не забудьте пароль, который вы задали!

Теперь вы готовы `установить зависимости Iroha <Установка зависимостей с помощью Vcpkg_>`_.

Установка зависимостей с помощью Vcpkg
======================================

В настоящее время мы используем Vcpkg как менеджер зависимостей для всех платформ — Linux, Windows и MacOS.
Мы используем фиксированную версию Vcpkg (закреплённую в ``vcpkg/VCPKG_COMMIT_SHA``), чтобы гарантировать, что нужные нам патчи будут работать.

Полный список требуемых зависимостей поддерживается в одном месте —
``vcpkg/VCPKG_DEPS_LIST`` — и приведён ниже. Vcpkg разрешает каждый порт
до новейшей версии, доступной в закреплённой базовой линии vcpkg; это **минимальные поддерживаемые версии** для успешной сборки:

.. literalinclude:: ../../../vcpkg/VCPKG_DEPS_LIST
   :language: text

.. note:: Если вы собираете вне vcpkg (например, системными пакетами), убедитесь, что ваши
  версии **не старше** тех, что предоставляет закреплённая базовая линия vcpkg.
  В частности, код требует **soci 4.x** (использует ``soci/std-optional.h``),
  **protobuf с генерацией кода gRPC**, **Boost >= 1.73** и **OpenSSL 3.x**.

Эту стабильную версию можно найти только внутри репозитория Iroha, поэтому нам нужно клонировать Iroha.
Весь процесс довольно похож для всех платформ, но точные команды немного различаются.

Linux и MacOS
^^^^^^^^^^^^^^

Выполните в терминале:

.. code-block:: shell

  git clone https://github.com/baziorek/iroha1-cpp.git
  cd iroha
  ./vcpkg/build_iroha_deps.sh $PWD/vcpkg-build

И это всё! Теперь вы можете перейти к разделу `Процесс сборки <Процесс сборки_>`_.

Windows
^^^^^^^

Выполните из Power Shell:

.. code-block:: shell

  git clone https://github.com/baziorek/iroha1-cpp.git
  cd iroha
  powershell -ExecutionPolicy ByPass -File .\.packer\win\scripts\vcpkg.ps1 .\vcpkg .\iroha\vcpkg


Отличная работа! Теперь вы можете перейти к разделу `Процесс сборки <Процесс сборки_>`_.

.. note:: Если вы планируете собирать 32-битную версию Iroha —
  вам нужно будет установить все упомянутые выше библиотеки
  с префиксом ``x86`` вместо ``x64``.

Процесс сборки
==============

Сборка Iroha
^^^^^^^^^^^^

1. Итак, после того как зависимости собраны, мы можем начать сборку самой Iroha: 

.. code-block:: shell

  cmake -B build -DCMAKE_TOOLCHAIN_FILE=$PWD/vcpkg-build/scripts/buildsystems/vcpkg.cmake . -DCMAKE_BUILD_TYPE=RELEASE   -GNinja -DUSE_BURROW=OFF -DUSE_LIBURSA=OFF -DTESTING=OFF -DPACKAGE_DEB=OFF

Параметры cmake, такие как ``-DUSE_BURROW=ON``, — это именно те параметры, которые вы можете выбрать для своей особой сборки. Полный список и описание этих параметров вы можете посмотреть `здесь <Параметры CMake_>`_.

2. Выполните 

.. code-block:: shell

  cmake --build ./build --target irohad

.. warning:: Если вы планируете использовать тесты позже, вместо сборки цели `irohad` нужно использовать эту:

.. code-block:: shell

  cmake --build ./build --target all 


3. Проверьте результат, запустив справку: 

.. code-block:: shell

  ./build/bin/irohad --help

Этот шаг покажет вам все параметры. И это всё! 

.. note:: При сборке под Windows не выполняйте это из Power Shell. Лучше используйте командную строку x64 Native tools.

Теперь Iroha собрана. Хотя, если хотите, вы можете собрать её с дополнительными параметрами, описанными ниже.

Если вас устраивают результаты, вы можете перейти к следующему шагу и `запустить экземпляр Iroha <../deploy/single.html>`_. 

Параметры CMake
^^^^^^^^^^^^^^^

Мы используем CMake для генерации платформенно-зависимых файлов сборки.
Он имеет множество флагов для настройки итоговой сборки.
Обратите внимание, что помимо перечисленных параметров могут быть полезны и переменные cmake.
Также, поскольку эта страница может устареть (или просто быть неполной), вы можете просмотреть пользовательские флаги через ``cmake -L``, ``cmake-gui`` или ``ccmake``.

.. hint::  Вы можете указывать параметры на этапе настройки cmake
  (например, cmake -DTESTING=ON).

Запуск тестов (необязательно)
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
Прежде всего, убедитесь, что вы `правильно собрали Iroha <Процесс сборки_>`_ для тестов.

После сборки Iroha имеет смысл запустить тесты, чтобы проверить работоспособность
демона. Вы можете запустить тесты с помощью этого кода:

.. code-block:: shell

  cmake --build build --target test

В качестве альтернативы вы можете выполнить следующую команду в папке ``build``

.. code-block:: shell

  cd build
  ctest . --output-on-failure

.. note:: Некоторые тесты будут завершаться с ошибкой без запущенного хранилища PostgreSQL,
  поэтому если вы не используете скрипт ``scripts/run-iroha-dev.sh``, запустите Docker-
  контейнер или создайте локальное подключение со следующими параметрами:

  .. code-block:: shell

    docker run --name some-postgres \
    -e POSTGRES_USER=postgres \
    -e POSTGRES_PASSWORD=mysecretpassword \
    -p 5432:5432 \
    -d postgres:9.5 \
    -c 'max_prepared_transactions=100'
