Команды
========

Команда изменяет состояние, называемое World State View, выполняя действие над сущностью (активом, аккаунтом) в системе.
Любая команда должна быть включена в транзакцию для выполнения действия.

Коды ошибок
-----------

Каждая команда может завершиться с числовым ``error_code``, сообщаемым в статусе транзакции.
Коды ``0``, ``1`` и ``2`` имеют одинаковое значение для всех команд
(``0`` = успех, ``1`` = внутренняя ошибка, ``2`` = нет разрешений);
коды ``>= 3`` являются специфичными для команды.

Канонические определения находятся в ``shared_model/interfaces/command_error_codes.hpp``,
который используется исполнителями команд (бэкенды Postgres и RocksDB)
и клиентскими библиотеками. Приведённая ниже таблица сводит коды для каждой команды
для быстрого справочного использования; после неё воспроизведён полный заголовок.
Если таблица и заголовок когда-либо разойдутся,
**источником истины является заголовок** — именно он
определяет то, что фактически генерируют исполнители.

``0``–``2``. Пространства имён ошибок ``AddSyncPeer``/``RemoveSyncPeer``
существуют в заголовке для функции синхронизации пиров, но пока ни одна
клиентская команда их не генерирует.

Коды ``1007`` и ``1008`` генерируются только исполнителем команд RocksDB
(тестовый бэкенд): ``1007`` = разрешение уже установлено
(``grant_permission``), ``1008`` = пустой публичный ключ (``remove_peer``).
В бэкенде Postgres нет эквивалентных кодов.

Добавить количество актива
--------------------------

Назначение
^^^^^^^^^^^

Назначение команды добавления количества актива — увеличить количество актива на аккаунте создателя транзакции.
Сценарий использования — увеличение количества изменяемого актива в системе, который может выступать в роли претензии на товар (например, деньги, золото и т. д.)

Схема
^^^^^

.. code-block:: proto

    message AddAssetQuantity {
        string asset_id = 1;
        string amount = 2;
        optional string description = 3;
    }

.. note::
    Обратите внимание, что из-за известной проблемы вы не получите никакого исключения, если передадите недопустимое значение точности.
    Допустимый диапазон: 0 <= precision <= 255


Структура
^^^^^^^^^

.. csv-table::
    :header: "Поле", "Описание", "Ограничение", "Пример"
    :widths: 15, 30, 20, 15

    "Asset ID", "id актива", "<asset_name>#<domain_id>", "usd#morgan"
    "Amount", "положительное количество актива для добавления", "> 0", "200.02"
    "Description", "описание транзакции", "Максимальная длина описания (устанавливается в блоке genesis, по умолчанию 100*1024)", "Mint assets"

Валидация
^^^^^^^^^

1. Актив и аккаунт должны существовать
2. Точность добавляемого количества должна быть равна точности актива
3. Создатель транзакции должен иметь роль с разрешениями на выпуск активов

Таким идентификатором является публичный ключ другого устройства или публичный ключ другого пользователя.

Добавить роль
-------------

Назначение
^^^^^^^^^^^

Назначение команды добавления роли — повысить аккаунт до одной из созданных в системе ролей, где роль — это набор разрешений, необходимых аккаунту для выполнения действия (команды или запроса).

Схема
^^^^^

.. code-block:: proto

    message AppendRole {
       string account_id = 1;
       string role_name = 2;
    }

Структура
^^^^^^^^^

.. csv-table::
    :header: "Поле", "Описание", "Ограничение", "Пример"
    :widths: 15, 30, 20, 15

    "Account ID", "id аккаунта, к которому добавляется роль", "уже существующий", "makoto@soramitsu"
    "Role name", "имя уже созданной роли", "уже существующая", "MoneyCreator"

Валидация
^^^^^^^^^

1. Роль должна существовать в системе
2. Создатель транзакции должен иметь разрешения на добавление роли (CanAppendRole)
3. У аккаунта, который добавляет роль, набор разрешений в его ролях является надмножеством добавляемой роли (т. е. никто не может добавить роль, более мощную, чем та, что есть у создателя транзакции)

Вызвать движок
--------------

Назначение
^^^^^^^^^^^

Назначение команды вызова движка — развернуть новый контракт в Iroha EVM или вызвать метод уже существующего смарт-контракта.
Выполнение смарт-контракта может потенциально изменить состояние реестра при условии, что транзакция, содержащая эту команду, принята в блок и блок зафиксирован.

Схема
^^^^^

.. code-block:: proto

    message CallEngine {
        string caller = 1;
        oneof opt_callee {
            string callee = 2;  // hex string
        }
        string input = 3;   // hex string
    }

^^^^^^^^^

    "Caller", "Iroha account ID аккаунта, от имени которого выполняется команда", "<account_name>@<domain_id>", "test@mydomain"
    "Callee", "EVM-адрес развёрнутого смарт-контракта", "20-байтовая строка в шестнадцатеричном представлении", "7C370993FD90AF204FD582004E2E54E6A94F2651"
    "Input", "Байт-код смарт-контракта для вновь развёртываемого контракта или ABI-encoded строка селектора метода контракта, за которой следует `набор его аргументов <https://solidity.readthedocs.io/en/v0.6.5/abi-spec.html>`_", "Hex string", "40c10f19000000000000000000000000969453762b0c739dd285b31635efa00e24c2562800000000000000000000000000000000000000000000000000000000000004d2"

^^^^^^^^^

1. Caller — это корректный Iroha account ID
2. Создатель транзакции имеет роль с разрешением can_call_engine или can_call_engine_on_my_behalf

Проверка
^^^^^^^^

1. Исходный аккаунт имеет этот актив в отношении AccountHasAsset [#f1]_
2. Количество — положительное число, а точность актива согласована с определением актива
3. У исходного аккаунта достаточно актива для перевода и количество не равно нулю
4. Исходный аккаунт может переводить средства, а целевой аккаунт может их получать (их роли имеют эти разрешения)
5. Длина описания меньше 100*1024 (сто килобайт) и меньше значения настройки 'MaxDescriptionSize', если она задана.

Сравнить и установить данные аккаунта
-------------------------------------

Назначение
^^^^^^^^^^

Назначение команды compare and set account detail — установить данные «ключ-значение» для заданного аккаунта, если старое значение совпадает с переданным.

Схема
^^^^^^

.. code-block:: proto

    message CompareAndSetAccountDetail{
        string account_id = 1;
        string key = 2;
        string value = 3;
        oneof opt_old_value {
            string old_value = 4;
        }
        bool check_empty = 5;
    }

.. note::
    Обратите внимание, что поле old_value является необязательным.
    Это связано с тем, что пара ключ-значение может не существовать.

Структура
^^^^^^^^^

    "Ключ", "ключ устанавливаемой информации", "`[A-Za-z0-9_]{1,64}`", "Name"
    "Значение", "новое значение для соответствующего ключа", "длина значения ≤ 4096", "Artyom"
    "Старое значение", "текущее значение для соответствующего ключа", "длина значения ≤ 4096", "Artem"

Проверка
^^^^^^^^

Три случая:

    Случай 1. Когда создатель транзакции хочет установить данные аккаунта для своего аккаунта и у него есть разрешения GetMyAccountDetail / GetAllAccountsDetail / GetDomainAccountDetail

    Случай 2. Когда создатель транзакции хочет установить данные аккаунта для другого аккаунта и у него есть разрешения SetAccountDetail и GetAllAccountsDetail / GetDomainAccountDetail

    Случай 3. Создателю транзакции было предоставлено разрешение SetAccountDetail и у него есть разрешение GetAllAccountsDetail / GetDomainAccountDetail
