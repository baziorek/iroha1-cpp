.. _wsv-storage:

==========================
Хранилище WSV (PostgreSQL)
==========================

World State View (WSV) — это представление состояния, которое узел Iroha
хранит в базе данных: аккаунты, активы, детали транзакций и прочее.
Физически это хранится в PostgreSQL (или RocksDB на старых сборках)
и становится доступно через слой Ametsuchi.

Структура WSV
-------------

WSV организован в виде множества таблиц, ключевых по типам сущностей:

- ``account`` — аккаунты и их баланс
- ``asset`` — пользовательские цифровые активы
- ``tx_status`` — статусы транзакций (подтверждена, отклонена и т.д.)
- ``peer`` / ``tx`` / ``command`` / ``query`` — служебные таблицы,
  поддерживающие консенсус и порядок обработки
- ``mst_*`` — таблицы мультиподписных транзакций

Каждая запись хранится в виде бинарной сериализации команд/запросов
Iroha, поэтому при прямом чтении БД данные выглядят как бинарные
блобы. Для инспекции используйте ``iroha-wsv-checker`` или запросы
Iroha через Torii.

Переиндексация WSV
------------------

Если хранилище повредилось или после миграции, узел может пересобрать
WSV из block store:

.. code-block:: shell

  irohad --config config.json --genesis_block genesis.block \
         --keypair_name node0 --exit_after_init

``--exit_after_init`` заставляет узел применить все блоки заново и
завершиться. Подробнее — :ref:`deploy-flags`.

Инструменты для работы с хранилищем
-----------------------------------

- **iroha-wsv-checker** — поставляется в релизных пакетах; проверяет
  целостность WSV, ищет расхождения
- **wsv_diff** — утилита сравнения двух дампов WSV (требует ``jq`` и
  ``psql``); полезна при отладке репликации между узлами

.. hint:: В ``example/`` репозитория есть скрипты для создания
  PostgreSQL-таблиц; полный список таблиц и полей генерируется при
  первом запуске узла миграциями Ametsuchi.
