Руководство по CLI: отправка первых транзакций и запросов
=========================================================

.. note:: Эта страница предполагает, что ``iroha-cli`` уже
  доступен — он входит в дистрибутив узла. См. :doc:`cli`, как
  получить его через Docker, AppImage или сборку из исходников.

Вы можете взаимодействовать с Irohой различными способами.
Вы можете использовать наши клиентские библиотеки,
чтобы писать код на различных языках программирования (например,
Java, Python, Javascript, Swift), который общается с Irohой.
Альтернативно вы можете использовать ``iroha-cli`` — наш
инструмент командной строки для взаимодействия с Irohой.
В рамках этого руководства давайте познакомимся с ``iroha-cli``.

.. Attention:: Хотя ``iroha-cli`` — пожалуй, самый простой способ
  начать работу с Irohой, он покрывает лишь часть возможных
  команд/запросов, поэтому пользовательский опыт может быть не
  лучшим. Если хотите помочь нам создать лучшую версию CLI,
  дайте нам знать!

.. raw:: html

  <script src="https://asciinema.org/a/6dFA3CWHQOgaYbKfQXtzApDob.js" id="asciicast-6dFA3CWHQOgaYbKfQXtzApDob" async></script>

Откройте новый терминал (обратите внимание, что контейнер Iroha
и ``irohad`` должны быть запущены) и подключитесь к контейнеру
``iroha``:

.. code-block:: shell

  docker exec -it iroha /bin/bash

Теперь вы снова в интерактивной оболочке контейнера Iroha.
Нам нужно запустить ``iroha-cli`` и передать имя аккаунта
нужного пользователя. В нашем примере аккаунт ``admin`` уже
создан в домене ``test``. Давайте используем этот аккаунт для
работы с Irohой.

.. code-block:: shell

  iroha-cli -account_name admin@test

.. note:: Полное имя аккаунта содержит символ ``@`` между именем
  и доменом. Обратите внимание, что у пары ключей то же имя.

Создание первой транзакции
^^^^^^^^^^^^^^^^^^^^^^^^^^

Теперь вы видите интерфейс ``iroha-cli``.
Давайте создадим новый актив, добавим немного актива на аккаунт
админа и переведём его на другой аккаунт. Для этого выберите
опцию ``1. New transaction (tx)``, введя ``tx`` или ``1`` в
консоль.

Теперь вы видите список доступных команд.
Давайте попробуем создать новый актив.
Выберите ``14. Create Asset (crt_ast)``.
Теперь введите имя вашего актива, например ``coolcoin``.
Затем введите ID домена. В нашем примере уже есть домен
``test``, так что используем его.
Потом нужно ввести точность актива
– количество цифр в дробной части.
Установим точность в ``2``.

Поздравляем, вы создали свою первую команду и добавили её в
транзакцию! Вы можете либо отправить её в Irohе, либо добавить
ещё команды ``1. Add one more command to the transaction
(add)``. Давайте добавим ещё команды, чтобы сделать всё за один
раз. Введите ``add``.

Теперь попробуем добавить немного ``coolcoin`` на наш аккаунт.
Выберите ``16. Add Asset Quantity (add_ast_qty)``, введите ID
актива – ``coolcoin#test``, целую часть и точность.
Например, чтобы добавить 200.50 — введите целую часть как
``20050`` и точность как ``2``, получится ``200.50``.

.. note:: Полное имя актива содержит символ ``#`` между именем
  и доменом.

Переведём 100.50 ``coolcoin`` с ``admin@test`` на ``test@test``,
добавив ещё одну команду и выбрав ``5. Transfer Assets
(tran_ast)``. Введите Source Account и Destination Account — в
нашем случае ``admin@test`` и ``test@test`` — Asset ID
(``coolcoin#test``), целую часть и точность (соответственно
``10050`` и ``2``).

Теперь нужно отправить нашу транзакцию пиру Iroha
(``2. Send to Iroha peer (send)``). Введите адрес пира (в нашем
случае ``localhost``) и порт (``50051``).
Ваша транзакция только что отправлена, и вы можете увидеть её
хеш. Вы можете использовать его для проверки статуса
транзакции.

Вернитесь в терминал, где работает ``irohad``.
Вы можете увидеть логи своей транзакции.

Ура! Вы отправили свою первую транзакцию в Irohе.

Создание первого запроса
^^^^^^^^^^^^^^^^^^^^^^^^

Теперь давайте проверим, были ли ``coolcoin`` успешно переведены
с ``admin@test`` на ``test@test``. Выберите
``2. New query (qry)``.
``8. Get Account's Assets (get_acc_ast)`` поможет проверить,
есть ли теперь у ``test@test`` ``coolcoin``. Сформируйте запрос
похожим образом, как вы делали с командами, и
``1. Send to Iroha peer (send)``.
Теперь вы можете увидеть информацию о том, сколько
``coolcoin`` есть у ``test@test``. Это будет выглядеть
примерно так:

.. code-block:: shell

  [2018-03-21 12:33:23.179275525][th:36][info] QueryResponseHandler [Account Assets]
  [2018-03-21 12:33:23.179329199][th:36][info] QueryResponseHandler -Account Id:- test@test
  [2018-03-21 12:33:23.179338394][th:36][info] QueryResponseHandler -Asset Id- coolcoin#test
  [2018-03-21 12:33:23.179387969][th:36][info] QueryResponseHandler -Balance- 100.50

Разве это не круто?
Вы отправили свой первый запрос в Irohе и получили ответ!

.. hint:: Чтобы получить информацию обо всех доступных командах и
  запросах, загляните в наш раздел API.

Будь плохим парнем
^^^^^^^^^^^^^^^^^^

Давайте попробуем быть плохими и обмануть Irohе. Например,
попробуем перевести больше ``coolcoin``, чем есть у
``admin@test``. Попробуйте перевести 100000.00 ``coolcoin`` с
``admin@test`` на ``test@test``. Снова перейдите к
``1. New transaction (tx)``, ``5. Transfer Assets (tran_ast)``,
введите Source Account и Destination Account — в нашем случае
``admin@test`` и ``test@test`` — Asset ID (``coolcoin#test``),
целую часть и точность (соответственно ``10000000`` и ``2``).
Отправьте транзакцию пиру Iroha, как раньше.
Что ж, он говорит

.. code::

  [2018-03-21 12:58:40.791297963][th:520][info] TransactionResponseHandler Transaction successfully sent
  Congratulation, your transaction was accepted for processing.
  Its hash is fc1c23f2de1b6fccbfe1166805e31697118b57d7bb5b1f583f2d96e78f60c241

`Ваша транзакция принята к обработке`.
Означает ли это, что мы успешно обманули Irohе?
Давайте попробуем посмотреть статус транзакции.
Выберите ``3. New transaction status request (st)`` и введите
хеш транзакции, который можно получить в консоли после
предыдущей команды. Отправьте его в Irohе.
Он отвечает:

.. code::

  Transaction has not passed stateful validation.

Очевидно, нет.
Наша транзакция не была принята, потому что не прошла
состоятельную валидацию, и ``coolcoin`` не были переведены.
Вы можете проверить статус ``admin@test`` и ``test@test``
запросами, чтобы убедиться (как мы делали раньше).

Опции ``iroha-cli``
-------------------

Помимо интерактивного режима, показанного выше, ``iroha-cli``
принимает флаги командной строки для неинтерактивного и
скриптового использования:

+==========================+==============================================================+
| Флаг                     | Описание                                                     |
+==========================+==============================================================+
| ``-account_name``        | ID аккаунта для работы (напр. ``admin@test``)                |
+==========================+==============================================================+
| ``-new_account``         | создать пару ключей аккаунта при первом запуске              |
+==========================+==============================================================+
| ``-key_path``            | каталог с ключами ``<name>.pub``/``<name>.priv``             |
+==========================+==============================================================+
| ``-pass_phrase``         | парольная фраза для зашифрованных приватных ключей           |
+==========================+==============================================================+
| ``-peer_ip``             | адрес узла Iroha (по умолчанию ``127.0.0.1``)                |
+==========================+==============================================================+
| ``-torii_port``          | порт Torii узла (по умолчанию ``50051``)                     |
+==========================+==============================================================+
| ``-tls_root_cert``       | путь к PEM-сертификату root; включает TLS-транспорт          |
+==========================+==============================================================+
| ``-json_transaction``    | отправить транзакцию в JSON вместо интерактивной             |
+==========================+==============================================================+
| ``-json_query``          | отправить запрос в JSON вместо интерактивного                |
+==========================+==============================================================+
| ``-genesis_block``       | сгенерировать файл genesis block и выйти                     |
+==========================+==============================================================+
| ``-genesis_transaction`` | транзакция, используемая при генерации genesis block         |
+==========================+==============================================================+
| ``-peers_address``       | список пиров для генерируемого genesis block                 |
+==========================+==============================================================+
| ``-interactive``         | запуск интерактивной оболочки (по умолчанию ``true``;        |
+================----------+--------------------------------------------------------------+
|                          | установите ``false`` для одноразового JSON-режима)           |
+--------------------------+--------------------------------------------------------------+

Например, чтобы отправить готовую JSON-транзакцию без
интерактивной оболочки:

.. code-block:: shell

  iroha-cli -account_name admin@test \
            -peer_ip 127.0.0.1 -torii_port 50051 \
            -json_transaction tx.json -interactive=false

Когда у Torii-эндпоинта узла включён TLS (см.
:doc:`../configure/torii-tls`), укажите ``-tls_root_cert`` на
PEM-сертификат узла — этот флаг работает и в интерактивном
режиме.
