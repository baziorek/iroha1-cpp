============================
Запуск одиночного экземпляра
============================

Обычно люди хотят запустить Irohу локально, чтобы попробовать
API и исследовать её возможности. Это можно сделать в локальном
или контейнерном окружении (Docker). Мы рассмотрим оба возможных
случая, но для упрощения развёртывания компонентов пира
*рекомендуется иметь установленный Docker на машине*.

Локальное окружение
-------------------

Под локальным окружением понимается процесс демона и Postgres,
развёрнутые без каких-либо контейнеров. Это может быть полезно
в случаях, когда возня с Docker нежелательна — обычно для
быстрого исследования функций.

Запуск сервера postgres
"""""""""""""""""""""""

Чтобы запустить сервер postgres локально, проверьте сайт
postgres `website
<https://www.postgresql.org/docs/current/static/server-start.html>`__
и следуйте их описанию. Обычно сервер postgres запускается
автоматически при старте системы, но это стоит проверить в
конфигурации системы.

Сервер базы данных Postgres можно инициализировать и запустить
вручную без обычной системной интеграции:

.. code-block::shell

   initdb ~/iroha/nodeX_db/
   ## Start server in background, logs will appear in current console
   postgres -D ~/iroha/nodaX_db/ -p5433 &
   createuser -s iroha_user -p5433

Выбранный порт ``5433`` (по умолчанию 5432) и пользователь базы
``iroha_user`` используются irohad для подключения к базе.
(См. `Параметры конфигурации
<../configure/index.html>` для подробностей.) База maintenance
``postgres`` создаётся по умолчанию, но если по какой-то причине
нужно другое имя, создайте её:

.. code-block::shell

   createdb iroha_mainteance -p5433


Запуск демона Iroha (irohad)
""""""""""""""""""""""""""""""""""""""

Есть список предусловий, которые нужно выполнить перед
продолжением:

* Сервер Postgres запущен
* Бинарник демона Iroha `irohad` собран и доступен в системе
* Файлы genesis block и конфигурации созданы
* Файл конфигурации использует корректные настройки подключения
  postgres
* Пара ключей для пира сгенерирована
* Это первый запуск Iroha на этом пире и вы хотите создать новую
  цепочку

.. Hint:: Что-то не совпадает со списком предположений? Обратитесь
  к разделу :ref:`deploy_troubles`.

При выполнении предположений остаётся только запустить процесс
демона со следующими параметрами:

+---------------+---------------------------------------------------------------+
| Параметр      | Значение                                                      |
+===============+===============================================================+
| config        | файл конфигурации, содержащий подключение postgres и значения |
|               | для настройки системы                                         |
| genesis_block | начальный блок в ledger                                       |
| keypair_name  | имена файлов приватного и публичного ключей без расширения,   |
|               | используемые пиром для подписи блоков                         |
+---------------+---------------------------------------------------------------+

.. Attention:: Указание нового genesis block через `--genesis_block`
  при уже существующих блоках в ledger требует установки флага
  `--overwrite_ledger`. Иначе демон завершится с ошибкой.

Пример команды оболочки для запуска демона Iroha:

.. code-block:: shell

    irohad --config example/config.sample --genesis_block example/genesis.block --keypair_name example/node0

.. Note:: если вы запускаете Irohу, собранную с `поддержкой HL
  Ursa <../integrations/index.html#hyperledger-ursa>`_, возьмите
  пример ключей и genesis block из `example/ursa-keys/`

.. Attention:: Если вы остановили демон и хотите использовать
  существующую цепочку — не передавайте параметр genesis block.


Docker
------

Чтобы запустить пир Iroha как одиночный экземпляр в Docker,
сначала нужно pull-нуть образ Iroha:

.. code-block:: shell

    docker pull hyperledger/iroha:1.6.0

.. note:: ``hyperledger/iroha:1.6.0`` — последний официальный
  образ Iroha 1 upstream — **не** используйте ``:latest``
  (устаревшую сборку 2022 года) или теги ``:develop``/``:main``
  (они теперь указывают на сборки Iroha 2).

Затем нужно создать окружение, чтобы образ работал без проблем:

Создание docker-сети
"""""""""""""""""""""

Контейнеры Postgres и Iroha должны работать в одной виртуальной
сети, чтобы быть доступны друг другу. Создайте сеть, введя
следующую команду (можно использовать любое имя, но в примере
используем *iroha-network*):

.. code-block:: shell

    docker network create iroha-network

Запуск Postgresql в контейнере
""""""""""""""""""""""""""""""""""

Аналогично запустите сервер postgres, подключив его к созданной
ранее сети и открыв порты для связи:

.. code-block:: shell

    docker run --name some-postgres \
    -e POSTGRES_USER=postgres \
    -e POSTGRES_PASSWORD=mysecretpassword \
    -p 5432:5432 \
    --network=iroha-network \
    -d postgres:9.5

Создание тома для хранения блоков
""""""""""""""""""""""""""""""""""""""""""""

Прежде чем запустить демона iroha в контейнере, нужно создать
постоянный том для хранения файлов блоков цепочки. Это делается
следующей командой:

.. code-block:: shell

    docker volume create blockstore

Запуск демона iroha в docker-контейнере
""""""""""""""""""""""""""""""""""""""""""""""""""""

Есть список предположений, которые стоит проверить перед
продолжением:

* Сервер Postgres работает в той же docker-сети
* Есть папка с файлом конфигурации и парой ключей для одиночного
  узла
* Это первый запуск Iroha на этом пире и вы хотите создать новую
  цепочку

Если они выполнены, можно переходить к следующей команде:

.. code-block:: shell

    docker run --name iroha \
    # External port
    -p 50051:50051 \
    # Folder with configuration files
    -v ~/Developer/iroha/example:/opt/iroha_data \
    # Blockstore volume
    -v blockstore:/tmp/block_store \
    # Postgres settings
    -e POSTGRES_HOST='some-postgres' \
    -e POSTGRES_PORT='5432' \
    -e POSTGRES_PASSWORD='mysecretpassword' \
    -e POSTGRES_USER='postgres' \
    # Node keypair name
    -e KEY='node0' \
    # Docker network name
    --network=iroha-network \
    hyperledger/iroha:1.6.0

.. note:: ``hyperledger/iroha:1.6.0`` — последний официальный
  образ Iroha 1 upstream — не используйте ``:latest``
  (устаревшую сборку 2022 года).

.. note:: При **первом запуске** Iroha перестраивает WSV из
  blockstore, что требует много памяти — на больших ledger это
  может привести к OOM-kill контейнера (см.
  `issue #1833 <https://github.com/hyperledger-iroha/iroha/issues/1833>`_).
  У docker-контейнеров по умолчанию нет лимита памяти, но на
  **Docker Desktop** (macOS/Windows) у всей VM есть лимит памяти —
  увеличьте его в *Settings → Resources* или передайте
  ``--memory`` в ``docker run`` на хостах Linux.
