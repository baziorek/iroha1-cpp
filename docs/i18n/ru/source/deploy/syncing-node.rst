=======================
Синхронизирующийся узел
=======================

**Синхронизирующийся узел** (syncing node) — это пир Iroha, который
следует за цепочкой, но не участвует в консенсусе: не создаёт
предложений, не голосует и не учитывается в кворуме. Его роль —
быстро поддерживать локальную копию world state view (WSV), например
для обслуживания запросов, в качестве read-реплики или для заполнения
нового полного узла — без затрат на полный консенсус-механизм.

Синхронизирующиеся пиры объявляются в сети так же, как обычные пиры:
сообщение ``Peer`` несёт флаг ``syncing_peer``, который устанавливается
командой `Add Peer <../develop/api/commands.html#add-peer>`_ (или в
genesis block). У аккаунта, отправляющего команду, должно быть
разрешение ``can_add_peer`` — точно так же, как для обычного пира.

Запуск узла
-----------

Запустите ``irohad`` с флагом ``--syncing_node``:

.. code-block:: shell

    irohad --config example/config.sample \
           --genesis_block example/genesis.block \
           --keypair_name example/node0 \
           --syncing_node

Флаг отображается в ``config.syncing_mode`` и используется при
инициализации ordering и консенсуса — узел пропускает голосование YAC
и вместо этого подтягивает подтверждённые блоки от пиров.

.. note:: Синхронизирующийся узел по-прежнему нуждается в корректной
  конфигурации, паре ключей и базе данных — он хранит блоки и WSV, как
  любой другой пир. Просто он их не производит и не голосует.

Полезные связанные флаги
------------------------

- ``--exit_after_init`` — перестраивает WSV из block store и завершается.
  Полезно для переиндексации после обслуживания или при смене
  backend'а хранения; см. :ref:`deploy-flags`.
- ``--wait_for_new_blocks`` — политика запуска, ожидающая новые блоки
  в локальном block store без запуска сети.
