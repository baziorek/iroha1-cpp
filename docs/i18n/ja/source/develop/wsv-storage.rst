===========================
WSV ストレージ (PostgreSQL)
===========================

World State View (WSV) は、Iroha ノードがデータベースに保持する
状態のビューです: アカウント、アセット、トランザクションの詳細
など。物理的には PostgreSQL（古いビルドでは RocksDB）に格納され、
Ametsuchi 層を通じてアクセス可能になります。

WSV の構造
----------

WSV はエンティティタイプごとにキー付けされた多数のテーブルで
構成されています:

- ``account`` — アカウントとその残高
- ``asset`` — ユーザー定義のデジタルアセット
- ``tx_status`` — トランザクションステータス（確定、拒否など）
- ``peer`` / ``tx`` / ``command`` / ``query`` — コンセンサスと
  処理順序をサポートするサービス用テーブル
- ``mst_*`` — マルチシグトランザクション用テーブル

各レコードは Iroha コマンド/クエリのバイナリシリアライゼーション
として保存されるため、DB を直接読むとデータはバイナリブロブに
見えます。検査には ``iroha-wsv-checker`` または Torii 経由の
Iroha クエリを使用してください。

WSV の再インデックス
--------------------

ストレージが破損した場合や移行後に、ノードはブロックストアから
WSV を再構築できます:

.. code-block:: shell

  irohad --config config.json --genesis_block genesis.block \
         --keypair_name node0 --exit_after_init

``--exit_after_init`` はノードにすべてのブロックを再適用させて
終了させます。詳細は :ref:`deploy-flags` を参照。

ストレージを扱うツール
----------------------

- **iroha-wsv-checker** — リリースパッケージに同梱。WSV の整合性を
  チェックし、不一致を検出
- **wsv_diff** — 2 つの WSV ダンプを比較するユーティリティ
  （``jq`` と ``psql`` が必要）。ノード間のレプリケーションの
  デバッグに便利

.. hint:: リポジトリの ``example/`` には PostgreSQL テーブルを
  作成するスクリプトがあります。テーブルとフィールドの完全な
  リストは、ノードの初回起動時に Ametsuchi マイグレーションによっ
  て生成されます。
