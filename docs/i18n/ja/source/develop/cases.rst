====================
ユースケースシナリオ
====================

Hyperledger Iroha がこれらのアプリケーションにもたらす
さまざまなユースケースと具体的な利点を挙げます。これらの
アプリケーションとユースケースが、開発者やクリエイターを
Hyperledger Iroha でのさらなるイノベーションへと
鼓舞することを願っています。


教育・医療における証明書
------------------------

Hyperledger Iroha は、大学、学校、医療機関など複数の
認証機関をシステムに組み込みます。Hyperledger Iroha の
柔軟な権限モデルにより、認証アイデンティティと付与される
証明書を構築できます。ユーザーアカウント内の明示的・暗黙的
情報の保存により、さまざまな評判・アイデンティティ
システムを構築できます。

Hyperledger Iroha を使うと、各教育・医療証明書が特定の
認証機関によって発行されたかを検証できます。不変性と
明確な検証ルールは、医療と教育に透明性をもたらし、
偽造証明書の使用を大幅に減らします。

例
^^

Hyperledger Iroha で ``hospital`` ドメインとして登録された
医療機関を想像してください。このドメインには認証・登録
された従業員がおり、それぞれ ``physician``、``therapist``、
``nurse`` などのロールを持ちます。病院の各患者は完全な
医療履歴を持つアカウントを持っています。血液検査の結果
などの各医療記録は、患者のアカウントに JSON の
キー/値として安全かつプライベートに保存されます。
``hospital`` ドメインのルールは、認証済み医療従事者と
ユーザーのみが個人情報にアクセスできるよう定義されて
います。クエリが返す医療データは、信頼できるソースから
来たことが検証されます。

病院は特定の場所に紐付けられ、その場所の法的ルール
(市民の個人データを特定の地域にのみ保存するなどの
``privacy rules``_) に従います。Hyperledger Iroha の
マルチドメインアプローチにより、法的ルールを侵害せずに
複数の国間で情報を共有できます。たとえば、ユーザー
``makoto@hospital`` が自分の症例履歴を他国の医療機関と
共有したい場合、``can_get_my_acc_detail`` 権限を持つ
``grant`` コマンドを使用できます。

医療機関と同様に、Hyperledger Iroha で登録された大学は
卒業生に情報をプッシュする権限を持ちます。卒業証書や
証明書は本質的に、認められた大学の署名付き
Proof-of-Graduation です。このアプローチは採用プロセスを
容易にします — 雇用主は Hyperledger Iroha にクエリして
潜在的な従業員の習得スキルと能力を取得できます。

.. _`privacy rules`: https://privacypolicies.com/blog/privacy-law-by-country/

国境を越えた資産移転
--------------------

Hyperledger Iroha は、マルチシグネチャアカウントと
アトミック交換を使って、高速で明確な取引・決済ルールを
提供します。資産管理は中央集権システムと同じくらい
簡単でありながら、必要なセキュリティ保証を提供します。
資産の作成と移転に必要なルールとコマンドを単純化する
ことで、参入障壁を下げながら、高いセキュリティ保証を
維持します。

例
^^

例えば [#f1]_、ユーザーが車の所有権を移転したい場合を
考えます。ユーザー ``haruto`` は ``sora`` ブランドの車と
``{"id": "34322069732074686520616E73776572", "color":
"red", "size": "small"}`` というパラメータで
所有者-資産関係を登録しています。この所有権はシステムの
基盤となるデータベースに記録され、各検証ピアにコピーが
あります。移転操作を実行するため、ユーザー ``haruto`` は
オファー、つまり 2 つのコマンドを持つマルチシグネチャ
トランザクションを作成します: 車の識別子をユーザー
``haru`` に ``transfer`` し、``haru`` から ``haruto`` へ
ある量の ``usd`` トークンを ``transfer`` するものです。
オファーを受け取った ``haru`` はマルチシグネチャ
トランザクションに署名して受け入れます。この場合、
トランザクションはアトミックにシステムにコミットされます。

Hyperledger Iroha には組み込みトークンはありませんが、
さまざまなクリエイターのさまざまな資産をサポートします。
このアプローチにより、分散型交換市場を構築できます。
例えば、システムには異なる国の中央銀行が資産を発行する
ことができます。

.. [#f1] 現在は未実装

金融アプリケーション
--------------------

Hyperledger Iroha は監査プロセスで非常に役立ちます。すべての
情報はビジネスルールで検証され、異なるネットワーク参加者
によって継続的に維持されます。アクセス制御ルールとある種の
暗号化により、望ましいプライバシーレベルが維持されます。
アクセス制御ルールはユーザーレベル、ドメインレベル、
システムレベルなど、さまざまなレベルで定義できます。
ユーザーレベルでは特定の個人のプライバシールールが定義
されます。アクセスルールがドメインまたはシステムレベルで
決定される場合、そのドメイン内のすべてのユーザーに影響
します。Hyperledger Iroha では、各ロールが特定の権限を
持つ、便利なロールベースのアクセス制御ルールを提供します。

トランザクションはローカルデータベースで追跡できます。
Iroha-API を使用して、監査人はデータへのクエリと分析を
実行し、特定の監査ソフトウェアを実行できます。
Hyperledger Iroha は分析ソフトウェアのデプロイにさまざまな
シナリオをサポートします: ローカルコンピュータ上で、
または特定のミドルウェア上でコードを実行します。この
アプローチにより、Hadoop、Apache などを使った Big Data
アプリケーションの分析が可能になります。Hyperledger Iroha
はデータの整合性とプライバシーの保証人として機能します
(クエリ権限の制限による)。

例
^^

例えば、監査は金融アプリケーションで役立ちます。監査人
アカウントには ``auditor`` ロールがあり、ユーザーに迷惑を
かけずにドメイン内のユーザー情報にアクセスする権限を
持ちます。アカウント乗っ取りの確率を下げ、監査人が悪意の
あるクエリを送信するのを防ぐため、監査人は通常マルチ
シグネチャアカウントとして定義されます。つまり監査人は
複数の個別のアイデンティティの署名がなければクエリを
実行できません。監査人はアカウントデータや残高を取得
するだけでなく、ユーザーのすべてのトランザクション、
例えばドメイン ``konoha`` でのユーザー ``haruto`` の
すべての送金もクエリできます。百万ユーザーのデータを
効率的に分析するため、各 Iroha ノードは分析ソフトウェアと
連携して動作できます。

マルチシグネチャトランザクションは Hyperledger Iroha の
強力なツールであり、税制を変革する可能性があります。
特定のドメイン内の各トランザクションは、1 つの署名が
ユーザー (例えば資産移転) から、2 つ目の署名が特別な
課税ノードから来るマルチシグネチャトランザクションに
なり得ます。課税ノードは Iroha-API を使って書かれた特別な
検証ルールを持ちます。例えば、認証済み店舗でのすべての
購入は税金を支払わなければなりません。言い換えれば、
Iroha での有効な購入トランザクションには 2 つのコマンド
が必要です: 店舗への送金 (購入) と政府への送金 (税金
支払い)。


アイデンティティ管理
--------------------

Hyperledger Iroha はアイデンティティ管理の組み込みサポートを
持っています。システム内の各ユーザーは個人情報を持つ一意に
識別されたアカウントを持ち、各トランザクションは署名され、
特定のユーザーに関連付けられます。これにより Hyperledger
Iroha は KYC (Know Your Customer) 機能を持つさまざまな
アプリケーションに最適です。

例
^^

例えば、保険会社はユーザーのトランザクション情報について
情報の真実性を心配せずにクエリすることで利益を得られます。
ユーザーも認証済み情報がクレーム処理時間を短縮するため、
ブロックチェーンに個人情報を保存することで利益を得られます。
ユーザーが住宅ローンを組みたい状況を想像してください。
現在、事前審査は収入、負債、情報確認に関する情報を収集する
面倒なプロセスです。Hyperledger Iroha の各ユーザーは、資産
所有、職位、負債などの検証済み個人情報を持つアカウントを
持っています。ユーザーの収入と負債は ``GetAccountTransactions``
クエリで、所有資産は ``GetAccountAssets`` クエリで、職位は
``GetAccountDetail`` で追跡できます。各クエリは検証済みの
結果を返すため、住宅ローンの処理時間は数秒で済みます。
ユーザーが個人情報を共有するインセンティブを与えるため、
さまざまな企業がビジネスプロセスを考案できます。例えば、
保険会社はフィットネス活動を行うユーザーにボーナス割引を
提供できます。フィットネスアプリはプライベートな
Proof-of-Activity をシステムにプッシュでき、ユーザーは後で
``can_get_my_acc_detail`` 権限を持つ ``GrantPermission`` を
使って保険会社と情報を共有するかどうかを決定できます。


サプライチェーン
----------------

分散型システムのガバナンスと法的ルールをシステムのコードと
して表現することは、あらゆるサプライチェーンシステムの
本質的な組み合わせです。Hyperledger Iroha で使われる認証
システムにより、物理的アイテムのトークン化とシステムへの
埋め込みが可能になります。各アイテムには「何が、いつ、
どこで、なぜ」の情報が含まれます。

権限システムと限定された安全なコアコマンドのセットは
攻撃ベクトルを狭め、努力なく基本的なプライバシーレベルを
提供します。各トランザクションはハッシュ値、資格情報、
またはクリエイターの証明書によってシステム内で追跡可能です。

例
^^

食品サプライチェーンは、農家、倉庫、食料品店、顧客など
複数の異なる参加者を持つ共有システムです。目標は食品を
農家の畑から顧客の食卓まで届けることです。製品は多くの
段階を経て、各段階が共有スペースに記録されます。顧客は
モバイルデバイスで製品のコードをスキャンし、その中に
Iroha クエリがエンコードされています。Iroha クエリは
すべての段階、製品情報、農家情報を含む完全な履歴を
提供します。

例えば、``gangreen`` は登録済み農家であり ``tomato`` 資産
のクリエイターで、物理的アイテムをトークン化する、つまり
各トマトを Iroha ``tomato`` アイテムに関連付ける保証人と
して機能します。資産作成と配布プロセスはネットワーク参加者
にとって完全に透明です。Iroha ``tomato`` は多数の販売者を
経て、最終的にユーザー ``chad`` のもとに届きます。

私たちは資産作成を複雑なスマートコントラクトを必要と
しない単一の ``CreateAsset`` コマンドに簡素化しました。
Hyperledger Iroha の主な利点の 1 つは、その容易さであり、
開発者がアプリケーションの提供価値に集中できるように
します。

基金管理
--------

マルチシグネチャトランザクションのサポートにより、複数の
マネージャーによる基金の維持が可能です。そのスキームでは
投資は参加者のクォーラムによる確認後にのみ行うことが
できます。

例
^^

基金の資産は 1 つのアカウントに保管されるべきです。
その署名者は投資とポートフォリオ分配を扱う基金マネージャー
であるべきです。これは ``AddSignatory`` コマンドで追加でき
ます。すべての資産は 1 つのアカウント内に保管され、その
署名者は基金マネージャーを代表します。このようにして、
具体的な取引はマルチシグネチャトランザクションで実行
でき、すべての人が特定の金融決定を決定します。1 人が
元のトランザクションとマネージャーの 1 人の署名を送信
することで取引を確認できます。Iroha はトランザクション
の送信を維持し、トランザクションのクォーラムパラメータで
パラメータ化された必要な確認数を受け取るまで取引は
完了しません。
