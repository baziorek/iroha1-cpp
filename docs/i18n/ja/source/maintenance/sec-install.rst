Iroha インストールのセキュリティヒント
======================================

このガイドは Iroha インストールを保護することを目的としています。
このガイドのほとんどのステップは自明に思えるかもしれませんが、将来
の潜在的なセキュリティ問題を回避するのに役立ちます。

物理セキュリティ
^^^^^^^^^^^^^^^^^

サーバーがローカル（物理的にアクセス可能）に配置されている場合、
多くのセキュリティ対策を適用する必要があります。クラウドホスティ
ングを使用している場合はこれらのステップをスキップしてください。

組織のポリシーおよび/またはアクセス制御システムを確立し、権限のあ
る職員のみがサーバールームにアクセスできるようにします。
次に、BIOS/ファームウェアのパスワードを設定し、ブート順序を設定し
て、代替メディアからの不正なブートを防ぎます。
そのような機能がある場合は、ブートローダーがパスワードで保護され
ていることを確認してください。また、CCTV 監視があると良いでしょ
う。

デプロイメント
^^^^^^^^^^^^^^

まず、`ソースコード
<https://github.com/baziorek/iroha1-cpp>`__（`hyperledger-iroha/iroha
<https://github.com/hyperledger-iroha/iroha/tree/iroha1-main>`__
のコミュニティフォーク）と `Docker イメージ
<https://hub.docker.com/r/hyperledger/iroha>`__ のダウンロードに
公式リポジトリが使用されていることを確認してください。
インストール中に使用されるデフォルトのパスワード（例: postgres へ
の接続パスワード）をすべて変更してください。
Iroha リポジトリには秘密鍵と公開鍵の例が含まれています — 本番環
境では絶対に使用しないでください。
さらに、新しい鍵ペアが安全な環境で生成され、管理者のみがそれらの
鍵ペアにアクセスできることを確認してください（または少なくとも
アクセスできる人数を最小限に抑えてください）。
Iroha ピアに鍵をデプロイした後、デプロイに使用したホストから秘密
鍵を削除してください。つまり、秘密鍵は Iroha ピア内のみに存在す
るべきです。
削除する前に秘密鍵の暗号化されたバックアップを作成し、アクセスを
制限してください。

ネットワーク設定
^^^^^^^^^^^^^^^^^

Iroha はポート 50051 と 10001 をリッスンし、TLS が有効な場合は
オプションで 55552 をリッスンします。
ファイアウォール設定は、これらのポートへの/からの着信/発信接続を
許可する必要があります。
可能であれば、リッスンポートを持つ他のネットワークサービス
（FTP、DNS、LDAP、SMB、DHCP、NFS、SNMP など）を無効化または削除
してください。
理想的には、Iroha はネットワークの観点から可能な限り分離されるべ
きです。

クライアント-ピア通信を暗号化したい場合は、torii ポートで TLS を
有効にできます。

トラフィック暗号化を使用しない場合、ピア間の通信を暗号化できる
任意のメカニズム、つまり VPN または Calico を使用して Docker
オーバーレイネットワークをセットアップすることを強くお勧めしま
す。
Docker swarm はデフォルトで通信を暗号化しますが、ファイアウォール
設定で必要なポートを開くことを忘れないでください。
VPN を使用する場合、VPN キーが他のユーザーに利用できないことを確
認してください。

SSH を使用する場合は、root ログインを無効にしてください。
それに加えて、パスワード認証を無効にし、鍵のみを使用してくださ
い。
SSH のログレベルを INFO に設定することも役立ちます。

IPv6 を使用しない場合、無効にすることが良い考えかもしれません。

更新
^^^^

最新のオペレーティングシステムセキュリティパッチをインストール
し、定期的に更新してください。
Iroha が Docker コンテナで実行されている場合は、Docker を定期的
に更新してください。
オプションではありますが、本番環境にインストールする前に別のサ
ーバーで更新をテストすることは良いプラクティスとされています。

ログと監視
^^^^^^^^^^^

- エージェント（例: Filebeat）を使用してログを収集し、専用マシン
  に送信します。
- すべての Iroha ピアからログを中央ポイント（例: Logstash）に収
  集します。
- ログと監視情報を暗号化されたチャネル（例: https）で転送します。
- 第三者がログにアクセスするのを防ぐ認証メカニズムを設定しま
  す。
- 第三者がログを送信するのを防ぐ認証メカニズムを設定します。
- すべての管理者アクセスをログに記録します。

OS 強化
^^^^^^^

次のステップは、Iroha の実行に Docker が使用されることを前提とし
ています。

- Docker Content Trust を有効にして設定します。
- 信頼できるユーザーのみが Docker デーモンを制御できるようにしま
  す。
- Docker コンテナリソースの制限を設定します。
