======================
トラブルシューティング
======================

ハードシャットダウン後の復旧
----------------------------

::

	[2020-11-27 10:40:01.764013860][th:1][warning] Irohad/Storage/FlatFileBlockStorage Error while block deserialization: Unexpected end of string. Expected a value.

	^

::

	[2020-11-25 10:36:19.993552669][C][Init]: Irohad startup failed: WSV state (height 4576773) is more recent than block storage (height 4576772).

このようなメッセージは、ファイルベースのブロックストアを使用中
にノードがクラッシュした場合に表示されることがあります。
別のノードから不足しているブロックをコピーしてください — この
場合、高速起動のために ``--reuse_state`` フラグを使用できます
— または空のファイルからブロックを削除し、既存のブロックから
WSV を再作成してください。

長時間のアイドル期間後のクライアント切断または "Rendezvous"
エラー
-------------------------------------------------------------------

クライアント（特に長寿命のステータスストリーム）が多くの時間
の非アクティブ後に Torii への接続を定期的に失う場合、原因は
通常、中間ホップ（NAT、ロードバランサー、プロキシ）のアイドル
タイムアウトが HTTP/2 接続を静かに切断することです。

このフォークの ``irohad`` は、すべてのサーバー（Torii、
internal ordering、utility）で **gRPC keepalive ping** を有効
にします: サーバーは 60 秒ごとにアイドル接続を ping し、20 秒
のタイムアウト後にデッド接続を閉じるため、クライアントは
半開きチャネルでハングするのではなくクリーンに再接続します。

それでも切断が見られる場合:

- keepalive 修正を含むビルドを使用していることを確認する
  （このフォーク、``iroha1-main`` ブランチ）
- クライアントとノードの間のプロキシ/LB に、keepalive 間隔
  より短い独自のアイドルタイムアウトがあるか確認し、引き上
  げる
- ステータスストリームでは、バックオフ付きの再接続を推奨 —
  :ref:`configuration` の ``stale_stream_max_rounds`` を参照
