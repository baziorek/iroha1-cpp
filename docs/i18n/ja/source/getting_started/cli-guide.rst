CLI ガイド: 最初のトランザクションとクエリの送信
=================================================

.. note:: このページでは ``iroha-cli`` がすでに利用可能であることを
  前提としています — ノードディストリビューションに同梱されていま
  す。Docker、AppImage、ソースビルドでの入手方法は :doc:`cli` を
  参照してください。

Iroha とはさまざまな方法で対話できます。
クライアントライブラリを使って、Iroha と通信するコードをさまざまな
プログラミング言語（Java、Python、Javascript、Swift など）で書く
ことができます。
あるいは、Iroha との対話用コマンドラインツール ``iroha-cli`` を
使うこともできます。
このガイドでは ``iroha-cli`` に慣れ親しんでいきましょう。

.. Attention:: ``iroha-cli`` は Iroha を使い始める最も簡単な方法
  ですが、利用可能なコマンド/クエリの一部しかカバーしていないた
  め、ユーザーエクスペリエンスが最良とは限りません。より良い CLI
  バージョンの構築を手伝っていただける場合はお知らせください!

.. raw:: html

  <script src="https://asciinema.org/a/6dFA3CWHQOgaYbKfQXtzApDob.js" id="asciicast-6dFA3CWHQOgaYbKfQXtzApDob" async></script>

新しいターミナルを開き（Iroha コンテナと ``irohad`` が起動して
いることに注意）、``iroha`` docker コンテナにアタッチします:

.. code-block:: shell

  docker exec -it iroha /bin/bash

Iroha コンテナの対話シェルに戻りました。
``iroha-cli`` を起動し、目的のユーザーのアカウント名を渡す必要が
あります。例では ``admin`` アカウントがすでに ``test`` ドメインに
作成されています。このアカウントを使って Iroha を操作しましょう。

.. code-block:: shell

  iroha-cli -account_name admin@test

.. note:: 完全なアカウント名は名前とドメインの間に ``@`` 記号を
  持ちます。鍵ペアも同じ名前であることに注意してください。

最初のトランザクションの作成
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

これで ``iroha-cli`` のインターフェースが見えます。
新しいアセットを作成し、admin アカウントにアセットを追加して別の
アカウントに転送しましょう。そのために、コンソールに ``tx`` または
``1`` と入力して ``1. New transaction (tx)`` を選択してください。

利用可能なコマンドのリストが表示されます。
新しいアセットを作成してみましょう。
``14. Create Asset (crt_ast)`` を選択します。
アセットの名前を入力します。例えば ``coolcoin``。
次にドメイン ID を入力します。例ではすでに ``test`` ドメインがあ
るので、それを使いましょう。
次にアセットの精度を入力する必要があります
— 小数部分の桁数です。
精度を ``2`` に設定しましょう。

おめでとうございます、最初のコマンドを作成し、トランザクションに
追加しました! Iroha に送信するか、さらにコマンドを追加できます
``1. Add one more command to the transaction (add)``。
さらにコマンドを追加して一度にすべて行いましょう。``add`` と入力
します。

アカウントに ``coolcoin`` をいくつか追加してみましょう。
``16. Add Asset Quantity (add_ast_qty)`` を選択し、アセット ID
— ``coolcoin#test`` — 整数部と精度を入力します。
例えば 200.50 を追加するには、整数部を ``20050``、精度を
``2`` と入力すると ``200.50`` になります。

.. note:: 完全なアセット名は名前とドメインの間に ``#`` 記号を持ち
  ます。

``admin@test`` から ``test@test`` へ 100.50 ``coolcoin`` を転送
しましょう。さらに 1 つコマンドを追加し、``5. Transfer Assets
(tran_ast)`` を選択します。Source Account と Destination
Account — この場合 ``admin@test`` と ``test@test`` — Asset ID
（``coolcoin#test``）、整数部と精度（それぞれ ``10050`` と
``2``）を入力します。

トランザクションを Iroha ピアに送信する必要があります
（``2. Send to Iroha peer (send)``）。ピアアドレス（この場合
``localhost``）とポート（``50051``）を入力します。
トランザクションが送信され、トランザクションハッシュが表示され
ます。これを使ってトランザクションのステータスを確認できます。

``irohad`` が動いているターミナルに戻ってください。
トランザクションのログが見えます。

やった! 最初のトランザクションを Iroha に送信しました。

最初のクエリの作成
^^^^^^^^^^^^^^^^^^^^

``coolcoin`` が ``admin@test`` から ``test@test`` に正常に転送さ
れたか確認しましょう。``2. New query (qry)`` を選択します。
``8. Get Account's Assets (get_acc_ast)`` が ``test@test`` に
``coolcoin`` があるか確認するのに役立ちます。コマンドと同様の方
法でクエリを作成し、``1. Send to Iroha peer (send)`` を使います。
``test@test`` がいくつ ``coolcoin`` を持っているかの情報が見えま
す。次のように表示されます:

.. code-block:: shell

  [2018-03-21 12:33:23.179275525][th:36][info] QueryResponseHandler [Account Assets]
  [2018-03-21 12:33:23.179329199][th:36][info] QueryResponseHandler -Account Id:- test@test
  [2018-03-21 12:33:23.179338394][th:36][info] QueryResponseHandler -Asset Id- coolcoin#test
  [2018-03-21 12:33:23.179387969][th:36][info] QueryResponseHandler -Balance- 100.50

すごいでしょう?
最初のクエリを Iroha に送信し、応答を受け取りました!

.. hint:: 利用可能なすべてのコマンドとクエリについては API セク
  ションを参照してください。

悪いことをしてみる
^^^^^^^^^^^^^^^^^^^^

Iroha をだましてみましょう。例えば ``admin@test`` が持っている
より多くの ``coolcoin`` を転送してみます。
``admin@test`` から ``test@test`` へ 100000.00 ``coolcoin`` を
転送してみてください。再び ``1. New transaction (tx)``、``5.
Transfer Assets (tran_ast)`` に進み、Source Account と
Destination Account — この場合 ``admin@test`` と ``test@test``
— Asset ID（``coolcoin#test``）、整数部と精度（それぞれ
``10000000`` と ``2``）を入力します。
以前と同様にトランザクションを Iroha ピアに送信します。
さて、こう返ってきます:

.. code::

  [2018-03-21 12:58:40.791297963][th:520][info] TransactionResponseHandler Transaction successfully sent
  Congratulation, your transaction was accepted for processing.
  Its hash is fc1c23f2de1b6fccbfe1166805e31697118b57d7bb5b1f583f2d96e78f60c241

`トランザクションは処理のために受理されました`。
Iroha をだますことに成功したという意味でしょうか?
トランザクションのステータスを見てみましょう。
``3. New transaction status request (st)`` を選択し、前のコマ
ンドの後にコンソールで取得できるトランザクションハッシュを入力
します。Iroha に送信します。
こう返ってきます:

.. code::

  Transaction has not passed stateful validation.

どうやらダメでした。
トランザクションは stateful validation を通過しなかったため受理
されず、``coolcoin`` は転送されませんでした。
確実にするためにクエリで ``admin@test`` と ``test@test`` のス
テータスを確認できます（以前と同様に）。

``iroha-cli`` オプション
------------------------

上記の対話モードに加えて、``iroha-cli`` は非対話・スクリプト用
途のコマンドラインフラグを受け付けます:

+==========================+==============================================================+
| フラグ                   | 説明                                                         |
+==========================+==============================================================+
| ``-account_name``        | 操作対象のアカウント ID（例: ``admin@test``）                |
+==========================+==============================================================+
| ``-new_account``         | 初回実行時にアカウント鍵ペアを作成                           |
+==========================+==============================================================+
| ``-key_path``            | ``<name>.pub``/``<name>.priv`` 鍵を含むディレクトリ          |
+==========================+==============================================================+
| ``-pass_phrase``         | 暗号化された秘密鍵のパスフレーズ                             |
+==========================+==============================================================+
| ``-peer_ip``             | Iroha ノードアドレス（デフォルト ``127.0.0.1``）             |
+==========================+==============================================================+
| ``-torii_port``          | ノードの Torii ポート（デフォルト ``50051``）                |
+==========================+==============================================================+
| ``-tls_root_cert``       | PEM ルート証明書へのパス; TLS トランスポートを有効化         |
+==========================+==============================================================+
| ``-json_transaction``    | 対話モードの代わりに JSON で記述されたトランザクションを送信 |
+==========================+==============================================================+
| ``-json_query``          | 対話モードの代わりに JSON で記述されたクエリを送信           |
+==========================+==============================================================+
| ``-genesis_block``       | genesis block ファイルを生成して終了                         |
+==========================+==============================================================+
| ``-genesis_transaction`` | genesis block 生成時に使用するトランザクション               |
++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++
| ``-peers_address``       | 生成される genesis block で使用するピアリスト                 |
++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++
| ``-interactive``         | 対話シェルを実行（デフォルト ``true``; ワンショット JSON モー |
++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++
|                          | ドには ``false`` を設定）                                    |
+================----------+--------------------------------------------------------------+

例えば、対話シェルなしで事前構築された JSON トランザクションを
送信するには:

.. code-block:: shell

  iroha-cli -account_name admin@test \
            -peer_ip 127.0.0.1 -torii_port 50051 \
            -json_transaction tx.json -interactive=false

ノードの Torii エンドポイントで TLS が有効な場合（
:doc:`../configure/torii-tls` 参照）、``-tls_root_cert`` にノード
の PEM 証明書を指定してください — 同じフラグは対話モードでも有効
です。
